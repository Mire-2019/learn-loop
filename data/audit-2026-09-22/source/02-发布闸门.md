# B 站发布前闸门（v1，2026-09-22 立，附首次盲评实测）

## 为什么要有它

用户口径：**播放量是结果指标，能力才是标准**。但"能力"如果不能被测，就退化成自评——所以把能力定义成三条可外部验证的过程指标：

| 能力指标 | 怎么测 | 谁能给结论 |
|---|---|---|
| 闸门通过率 | 发布前 G1–G4 是否全部跑过、是否有否决发生 | 代码（缺一次就是自欺） |
| 盲评排名 | 封面/标题与同题竞品混排，**盲评者不知道哪张是我们的** | 外部视觉模型 + 用户 |
| 相对数据 | 24h/72h 播放 ÷ 同账号基线（本账号基线：多数 34–71，最高 4925） | B 站接口 |

破万是这三条的**产物**，不是打分口径。只能控制过程，不能直接控制结果。

## 四道闸门（任意一道不过 → 不发，或只改一格再发）

- **G1 需求**：目标观众会搜的词必须有量（`bili_search.py kw`）；同题 Top10 形态表（标题句式/封面/时长/分区/UP 量级）。判据：**有人搜、但做得烂**。
- **G2 钩子**：`blind_cover_test.py` 把我们的封面与同题竞品混排盲评；标题前 12 字含被搜的词；开场 5 秒有可视物 + 反常识断言。
- **G3 交付**：3 分钟内能给一个可验证的东西（真仓库 + 一条能立刻跑的命令）。
- **G4 形态**：时长/节奏对齐同题头部；**不接受"静态幻灯片 + 机器配音"默认上线**。

## 首次实测证据（2026-09-22，针对已发布的 BV1txhk65Eje）

`blind_cover_test.py --seed 7`，5 张封面打乱 → GLM（不知哪张是我们的）排序：

```
E > B > D > C > A        B = 我们的封面
E = 北大团队发现 DeepSeek 严重 bug（107 万播放）
```

模型的原文理由：E 赢在「权威背书 + 热点 + 一句话就能解决的好奇」；最不想点的是电影海报式排版（"看不出讲什么"）。

**结论：封面排第 2，不是低流量主因。**对照同题头部的形态差：

| | 时长 | 标题里的词 |
|---|---|---|
| 我们 | 135s | "抽查 AI 的笔记"（**自造词，搜索框里没人这么搜**） |
| AI幻觉：从胡说八道到假装听话的进化史 | 426s（234 万） | "AI 幻觉"（被搜的真词） |
| 靠这台读书机器，我成了顶级学霸 | 561s（124 万） | "读书机器/学霸"（需求词） |

主因排序：**① 需求入口（标题/关键词）② 形态（时长 + 无真实录屏）③ 开场钩子 ④ 封面**。

## 资源为什么没变成能力（同一教训的第二次发作）

- `bili_search.py`（我自己写的需求侦察工具）**发布前一次没跑**；
- GLM 视觉通道早通着，**第一次真的用它做盲目评测是 09-22 凌晨**（就在写这份文档时）；
- JEV 判定层建好了，视频这条链**零调用**。

根因与 OV 里 JEV 那条一模一样的病：**工具存在 ≠ 该用的时候会用**。机制必须钉进**流程里必然走到的那一格**（发布前必须执行的脚本），否则"我知道我有它"不产生任何行为改变。

## 自进化的验法（用户口径）

1. 下一条片子发布前，G1–G4 全部有**外部产出物**（搜索数据 / 盲评回答 / 交付物链接 / 形态对照表），缺一个不算跑过。
2. 数据出来后做归因：哪一格失败 → 只改那一格 → 再发。**连续两版同一格失败，说明闸门本身不合格，改闸门不是改片子。**
3. 三次之后回看：盲评排名与相对数据是否真的右移。没右移＝这套闸门是装饰。
